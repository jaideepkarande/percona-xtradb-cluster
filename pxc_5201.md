# PXC-5201 — Native Automatic Asynchronous Replication Failover for Multi-Datacenter PXC Clusters

This document is the engineering write-up for PXC-5201. It explains *what* was
built, *why* the design looks the way it does, *every* file that was added or
changed, and *how* the feature is exercised by the MTR test-suite. The
user-facing manual lives in [`DESIGN/documentation.md`](DESIGN/documentation.md);
the formal design lives in the other `DESIGN/*.md` files.

---

## 1. Problem recap

Two independent 3-node Galera clusters (D1 primary, D2 DR) are linked by a single
classic MySQL **asynchronous** replication channel (one source node in D1, one
replica node in D2). That async link is a single point of failure:

* **Scenario A — replica node dies (D2):** replication to the DR site stops
  until a DBA manually points another D2 node at the source.
* **Scenario B — source node dies (D1):** the replica must re-point at a
  surviving D1 node. MySQL 8.0 Asynchronous Connection Failover (ACF) can do
  this, but the candidate-source list has to be built and maintained by hand.

PXC-5201 makes PXC manage this link itself, driven by Galera cluster
membership, with three safety requirements called out by the developer:

1. verify **GTID consistency** before touching replication,
2. keep the DR cluster in **`super_read_only`** (no split brain),
3. require **`gtid_mode=ON` / `enforce_gtid_consistency=ON`**.

---

## 2. Solution at a glance

A new singleton, the **Cluster-Aware Asynchronous Replication Failover
Coordinator** (`Wsrep_async_failover`), runs one background thread per node. It:

* is notified of every Galera **view change** (membership change) through
  `Wsrep_server_service::log_view()`;
* performs a **deterministic, message-free election** of the active replica
  using the totally-ordered wsrep status globals (`wsrep_cluster_status`,
  `wsrep_cluster_size`, `wsrep_local_index`). The member at wsrep index `0` of
  the primary component is the active replica — every node computes the same
  answer without extra coordination;
* on the elected node (RECEIVER mode): runs the **GTID consistency gate**,
  enforces **`super_read_only`** on the DR cluster, and issues
  `START REPLICA` for the managed channel (only if a source is configured);
* on non-elected nodes: issues `STOP REPLICA` so exactly one replica is ever
  active (Scenario A);
* in SOURCE mode: keeps the ACF candidate-source list aligned with the live
  members of the primary cluster by driving the existing ACF UDFs, so MySQL's
  own ACF receiver thread transparently re-points on source failure
  (Scenario B);
* exposes its full state through a new Performance Schema table,
  `performance_schema.wsrep_async_failover_status`.

All blocking work (SQL, `START`/`STOP REPLICA`, `SET GLOBAL super_read_only`)
happens on the **background thread** via the internal `Ed_connection` API —
never inside the total-order view callback, which only snapshots membership and
signals the worker.

## 3. New configuration surface (system variables)

Registered in `sql/sys_vars.cc`, declared in `sql/wsrep_mysqld.h`, defined in
`sql/wsrep_mysqld.cc`:

| Variable | Type | Default | Meaning |
|---|---|---|---|
| `wsrep_async_failover` | bool | `OFF` | Master switch. Starts/stops the coordinator thread. |
| `wsrep_async_failover_mode` | enum | `OFF` | `OFF` / `RECEIVER` / `SOURCE` / `BOTH`. |
| `wsrep_async_failover_channel` | string | `''` | Managed async channel (empty = default channel). |
| `wsrep_async_failover_gtid_check` | enum | `ENFORCE` | `OFF` / `WARN` / `ENFORCE` GTID gate policy. |
| `wsrep_async_failover_read_only` | bool | `ON` | Hold `super_read_only` on the DR cluster. |
| `wsrep_async_failover_check_interval` | uint (1–3600) | `5` | Re-evaluation period in seconds. |

`ON_UPDATE` callbacks (`sql/wsrep_var.cc`):
* `wsrep_async_failover_update` → `refresh_enabled()` (start/stop the worker);
* `wsrep_async_failover_wakeup_update` → `wakeup()` (apply other changes
  promptly without waiting for the timer).

## 6. Key implementation details & decisions

### 6.1 Deterministic election from wsrep globals
Rather than tracking ephemeral `wsrep::view` objects across the thread boundary,
`compute_election()` reads the status globals that `log_view()` already
publishes under lock:

```
primary  = (wsrep_cluster_status == "Primary")
elected  = primary && wsrep_cluster_size > 0 && wsrep_local_index == 0
```

Galera orders members identically on every node, so the index-0 rule needs no
extra messaging and is robust against a missed callback (the periodic timer
re-evaluates anyway). The coordinator **never acts outside a Primary
component**, which is the core split-brain guard.

### 6.2 Background thread + internal SQL
The worker is created with `create_internal_thd()` (proper `THD`, PSI
instrumentation, `COM_DAEMON`, `wsrep_on=false` so its control statements are
never replicated). All SQL goes through small `Ed_connection` helpers
(`acf_exec`, `acf_query_scalar`, `acf_query_rows`) so we reuse the same battle-
tested execution path the server uses internally.

### 6.3 GTID consistency gate
`gtid_gate()` implements the `OFF`/`WARN`/`ENFORCE` policy. v1 focuses on
**errant transactions**:

* If nothing has been received on the channel yet, there is no source baseline
  to compare against → verdict `OK` (nothing to gate).
* Otherwise `errant = gtid_executed − received − (server_uuid:1-MAX)`. A
  non-empty remainder means transactions that came from neither the managed
  source nor this node. Under `ENFORCE` the replica is **not** started; under
  `WARN` it is started with a logged warning.

Two correctness fixes were made here during testing:
* the interval upper bound must be `9223372036854775806` (2^63-2); the absolute
  max `2^63-1` is rejected by the GTID-set parser as "Malformed GTID set";
* the empty-`received` early return avoids flagging a clean node's own cluster
  GTIDs as errant.

The multi-UUID caveat (`wsrep_gtid_mode` shares one cluster UUID; mixed-UUID
histories are harder) is documented in `DESIGN/low_level_design.md`.

### 6.4 `super_read_only` management
When acting as RECEIVER/BOTH with `wsrep_async_failover_read_only=ON`, the
coordinator enables `super_read_only` on the DR cluster and records that it
holds the bit (`SUPER_READ_ONLY_MANAGED`). It is intentionally **not** released
on `OFF`/disable — leaving the DR read-only is the safe default; an operator
clears it explicitly. This mirrors InnoDB Cluster behaviour.

### 6.5 Scenario B without forking ACF
Instead of re-implementing failover, the coordinator keeps the ACF candidate
list current and lets MySQL's existing ACF receiver thread do the reconnect.
The `GaleraCluster` managed type teaches
`asynchronous_connection_failover_add_managed` to register a PXC source cluster;
`process_source()` reconciles the managed source list via the existing ACF UDFs.

### 6.6 `START REPLICA` guard
`process_receiver()` only issues `START REPLICA` when the channel actually has a
configured source (`replication_connection_configuration.HOST <> ''`). This
avoids noisy "server is not configured as replica" errors when the coordinator
is enabled before the channel is provisioned.

## 7. Observability — `performance_schema.wsrep_async_failover_status`

One row per node:

| Column | Meaning |
|---|---|
| `ENABLED` | Coordinator enabled on this node. |
| `MODE` | `OFF` / `RECEIVER` / `SOURCE` / `BOTH`. |
| `CHANNEL_NAME` | Managed channel. |
| `IS_ACTIVE_REPLICA` | This node is the elected active replica. |
| `ELECTED_INDEX` | wsrep index of the elected replica (`-1` if none). |
| `CLUSTER_SIZE` | Members in the current primary component. |
| `GTID_CONSISTENCY` | Last gate verdict: `OK` / `ERRANT` / `SKIPPED`. |
| `SUPER_READ_ONLY_MANAGED` | Coordinator is holding `super_read_only`. |
| `LAST_ACTION` | Human-readable last decision. |
| `LAST_ACTION_TIMESTAMP` | When it was taken (nullable). |

## 8. Tests

Both tests pass in `enc_off` and `enc_on` variants:

```
$ ./mysql-test-run.pl --suite=galera galera.pxc_5201_basic galera.pxc_5201_managed_type
...
Completed: All 5 tests were successful.
```

* **`pxc_5201_basic`** — verifies sysvar defaults, the P_S table, enum
  validation, deterministic self-election on a single-member primary,
  automatic `super_read_only`, the `OK` GTID verdict, and clean enable/disable.
* **`pxc_5201_managed_type`** — verifies the ACF UDF accepts `GaleraCluster`,
  still accepts `GroupReplication` (no regression), and rejects unknown types
  with `ER_CANT_INITIALIZE_UDF`. Cleanup calls
  `asynchronous_connection_failover_reset()` so the persistent
  configuration-version table matches the pre-test baseline
  (keeps `check-testcase` green).

The broader multi-cluster matrix (real receiver/source failover across two
3-node clusters) is specified in `DESIGN/testing_plan.md` as `big_test`
scenarios for the CI environment.
